## Task

We need to separate **real user accounts** from the **"Continue with Demo" account** so that mock/synthetic data only ever appears in the demo path, never for a real new user.

### Context
- This is the BrainMVB platform (Brain's reference client UI), which talks to brain-core's Brain APIs (ledger, wiki, policy, agent, audit layers).
- Today, some mock/synthetic data (e.g. the Northlight Manufacturing dataset or other placeholder sources/connections) may be leaking into real new-user account flows. This needs to stop.
- The demo experience must stay fully realistic and impressive — it should just be *seeded* rather than live-ingested.

### Required behavior

**1. Real (non-demo) new accounts**
- On signup/onboarding, a real account must start with **zero connected sources, zero ledger entries, zero raw-layer ingestion** — a genuinely empty state.
- Audit every code path (seed scripts, fixtures, default DB rows, frontend fallback/placeholder data, hardcoded arrays, "if no data show sample" logic) that could inject mock data into a real tenant. Remove or gate all of it behind an explicit `isDemo` flag.
- Empty states in the UI (dashboard, sources, agents, audit log, etc.) should be genuine "no data yet — connect a source" states, not disguised mock data.

**2. "Continue with Demo" button**
- Keep using real Brain APIs for everything **downstream of ingestion** — ledger, wiki, policy, agent recommendations, audit trail must all be live calls against brain-core, exactly as a real account would experience them.
- What we simulate is only the **Raw layer (ingestion)**: pre-seed a demo tenant so it looks like the user already connected sources (e.g. bank/Plaid, accounting/Merge, payroll/Finch, email/document) and that ingestion already ran successfully.
- Concretely: when "Continue with Demo" is clicked, provision/reuse a **demo tenant** whose Raw layer is pre-populated with the existing synthetic dataset (Northlight Manufacturing or equivalent), then let the normal Brain API pipeline (Ledger → Wiki → Policy → Agent → Audit) run on top of that seeded raw data exactly as it would for a real tenant with real ingested data.
- The user should land in a dashboard that shows "Sources: Connected" (bank, accounting, etc. — marked as demo/simulated in metadata, not in the visible UI unless we already do that) with live agent recommendations, ledger activity, and audit trail generated by the real Brain APIs from that seeded raw data — not hardcoded frontend mock JSON.
- Respect the existing demo tenancy behavior already in the platform (per-session demo tenant auto-provisioned, ~30 min lifetime, cannot be created manually) — extend that mechanism to pre-seed the Raw layer rather than building a parallel demo system.

### Explicitly out of scope / do not change
- Do not touch production tenant creation flow beyond removing mock-data leakage.
- Do not fake or hardcode Ledger/Wiki/Policy/Agent/Audit responses in the frontend for the demo — those must still come from brain-core.
- Do not modify brain-core contracts/endpoints from this repo (BrainMVB is UI-side; if a brain-core change is required to seed raw-layer data for a tenant, stop and flag it instead of working around it with frontend mocks).

### Process requirements
- `git fetch` and `git pull` before starting, and work on a new feature branch (not main).
- Before writing code, produce a short plan listing: (a) every location currently injecting mock/demo data into real accounts, (b) the seeding mechanism you'll use for the demo tenant's raw layer, (c) what stays a live Brain API call.
- Keep a running done/pending checklist as you execute the plan (in the PR description or a scratch file), and update it as tasks complete.
- Update `CLAUDE.md` with what changed: how demo-tenant raw-layer seeding works, where the `isDemo` flag is checked, and where mock data used to leak from.
- Definition of done: real signup produces a genuinely empty account with no mock data anywhere in the UI or API responses; "Continue with Demo" produces a fully populated experience sourced from seeded raw-layer data plus live Brain API calls; PR merged to main with CI green.
